## Decisions

- Курсор строится по ключу ранга (покрытие, город, время, id), а не по смещению: порядок стабилен при равных временах. Ранг считается в памяти по лёгкой сводке (id, город, время, теги) всех открытых чужих запросов, полные данные грузятся только для страницы (why: покрытие тегов в SQL не посчитать).
- Карта остаётся при потолке 200 новейших чужих запросов (пины листать нельзя); лента потолка не имеет.
- Запрос без бюджета не отсекается порогом минимального бюджета; запрос без города («Віддалено») проходит любой выбор городов (why: неизвестное не считаем «ниже»).
- Объединение двух endpoint в один расчёт не делали: кеш между запросами рискует отдать список без только что опубликованного запроса. Вместо этого лента не читает карту и свою историю, а jitter разводит клиентов.
- Миграция не нужна: настройки лежат JSON-ом в `notification_preferences.prefs`.
