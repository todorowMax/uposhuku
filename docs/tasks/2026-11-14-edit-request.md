# Редактирование своего запроса

- Created: 2026-11-14
- Project / repo: uposhuku
- Final status: done (код і перевірка локально), не виложено на dev

## Goal

Владелец: «хочешь что-то поменять, а не можешь». Сейчас запрос можно только создать или закрыть: `PATCH /api/requests/:id` принимает лишь `{status: "closed"}`, в меню «⋯» на панели «Мої запити» одна кнопка «Закрити запит». Нужно дать автору править открытый запрос: текст, теги, бюджет, срок, город, файлы (описания) и галочку публикации в Telegram-канале.

## Done criteria

- [ ] Автор открытого запроса меняет текст, теги, бюджет, срок, город и согласие на канал; изменение видно на карте, в списке исполнителей и в «Мої запити» без перезагрузки.
- [ ] Чужой или закрытый запрос не редактируется (404 и 409), лимит частоты правок есть.
- [ ] Исполнители, которые уже видят запрос, видят пометку «Змінено» и время правки; сделки и условия, созданные до правки, не меняются.
- [ ] Пост в Telegram-канале обновляется, если уже опубликован; если ещё нет, публикуется свежая версия.
- [ ] Экран правки проверен на 375 px и на десктопе, с клавиатуры; текст не вылезает (длинное слово без пробелов).
- [ ] `lint:ci`, `typecheck`, `npm test` зелёные; новые тесты падают без правки.
- [ ] Выложено на dev после проверки.

## Решения по умолчанию (владелец может отменить)

- Править можно в любой момент, пока запрос `open`. Закрытый не редактируется и не «переоткрывается» (отдельная задача, если понадобится).
- Правка не создаёт новых уведомлений «новый запрос под ваши теги»: иначе спам. Исполнителям, которые уже откликнулись, пишем в разговор одну служебную строку «Замовник оновив запит», без текста изменений.
- Уже созданные сделки не трогаем: условия лежат в самой сделке (`stage`, «Що вважаємо готовим» фиксируется при создании).
- История правок не хранится, только `edited_at` и `edit_count` (достаточно для пометки и лимита). Если для споров нужен прежний текст, это отдельная таблица.
- Правка не продлевает «свежесть» запроса: порядок в списке по `created_at` не меняется.

## Lessons (candidates)

- Невидима копія для виміру (`.tag-row-measure`) у `nowrap`-рядку роздувала `scrollWidth` предка, коли рядок потрапив у прокручуваний екран; перевіряти `scrollWidth` не лише композера, а й кожного нового місця, де вставляють спільний компонент.
- Скриншоти панелі браузера запізнюються на один крок: після кліку чекати й знімати двічі, зміну стану підтверджувати через DOM або `fetch`.

## Not verified

- На dev нічого не застосовано: міграція 0022 і сама правка перевірені лише локально.
- Мітка «Змінено» на карті: перевірено лише дані (`/api/map/requests` віддає `editedAt`) і мітку в списку «Запити для вас»; картку цього запиту на карті не відкривав (він віддалений, без міста), та сама `FeedCard` покрита тестом пункту 2.
- Файли: додавання й зняття перевірено тільки на рівні логіки й тесту `edit-draft`, у браузері вибір файла не пробував; файли лишаються описом, нічого не завантажується.
- «Віддалено» в чипі «Де» при відкритті правки не відновлюється: збережені `cityId = null` для «Віддалено» і «не вказано» однакові, тож чип стоїть порожнім. На збереження це не впливає.
- Перегляд екрана на планшеті (768-1099 px), темну тему, скрінрідер (лише `role=status` у DOM) і слабкий мобільний мережевий режим не перевіряв.
- Правка під час публікації в канал і поведінка при знятій галочці каналу для вже опублікованого поста: сервер оновлює лише існуючий пост (пункт 3), чи ховати/видаляти пост при знятій галочці, не вирішено.
- Два одночасні вікна автора, що правлять один запит: остання правка перемагає, попередження немає.
- Повний `npm test` пройшов з першого разу, флейків `n-plus-one`/`repos` цього разу не було.
