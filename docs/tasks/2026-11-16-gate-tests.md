## Знайдені помилки в логіці воріт (не виправлено)

Явних помилок, що пропускають гроші чи згоду, не знайдено. Одна неточність у відповіді:

1. `lib/server/deal-pay.ts`, `startStagePayment`: при незаданому `MONOBANK_SPLIT_TOKEN` відповідь 502 «Банк не відповів. Гроші не
   списано, спробуйте ще раз за хвилину», а не 503 «Оплата тимчасово недоступна».
   - Вхід: безпечна угода зі статусом `accepted`, етап `pending`, у оточенні немає `MONOBANK_SPLIT_TOKEN`.
   - Очікувано (за кодом): гілка `!terminalToken("split")` дає `fail(503, "Оплата тимчасово недоступна", ...)`.
   - Фактично: до цієї перевірки `freshReceiverId` читає список отримувачів терміналом `split`, `getMonobankToken` кидає звичайну
     `Error`, її ловить `catch { return BANK_DOWN }`, тож приходить 502. Права половина умови `|| !terminalToken("split")`
     недосяжна: токен уже перевірено раніше, неявно.
   - Наслідок: гроші не рухаються (резерву й рахунку немає, тест це перевіряє), але людина бачить хибну причину «банк не відповів»,
     а не «оплата недоступна». Виправлення (перевірити токен й отримувача платформи до `freshReceiverId`) торкається платіжного
     коду, тож лишаю власнику.

## Decisions

- Код воріт не змінювався: лише тести (CORE-7). Мутації робились у робочій копії й відкочувались правкою файла назад, у коміти не
  потрапили (stays here).
- `phone-gate` нових тестів не отримав: його гілки вже покриті маршрутними тестами, а пряма перевірка їх повторила б (stays here).
- JSON підключається типізованим імпортом: `import data from "./companions.json"` і `export const COMPANIONS: Record<string, Record<string, number>> = data`.
  `resolveJsonModule` у `tsconfig.json` уже був увімкнений (stays here).
- Ключі в JSON лишені в тому самому порядку й форматі «один тег на рядок», щоб діф переносу читався (stays here).

## Lessons (candidates)

- Тест воріт, який ходить лише через маршрут, не бачить, яка саме відмова спрацювала: маршрут часто зводить різні причини до
  одного коду. Для воріт корисно мати і прямий тест на текст і порядок відмов.
- Хук `ratchet-update` у `lefthook` сам знижує `--max-warnings` у `package.json` і додає зміну до коміту: першим комітом
  планка пішла з 414 на 413. Паралельні гілки, що теж зачіпають лінт, матимуть конфлікт у цьому рядку.
