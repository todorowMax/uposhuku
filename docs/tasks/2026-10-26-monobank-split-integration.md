- Created: 2026-10-26
- Project / repo: uposhuku

## Goal

Заменить «тестовую оплату» безопасной сделки реальными платежами Monobank: заказчик замораживает сумму «к оплате» (холд до 30 дней), после приёмки банк делит её между исполнителем-ФОП и платформой, споры решаются финализацией или возвратом по частям. Всё за флагом `SAFE_DEAL_ENABLED` (сейчас `false`), на прод не выкатываем без отдельного разрешения. Почему сейчас: банк подключил сплит, тест 26.10 показал, как он работает.

## Decisions

- Корзина этапа режется на 20 равных частей исполнителя и 20 частей платформы (шаг выплаты 5 %). Банк принял до 400 позиций в счёте, финализация работает по позициям, произвольная сумма не проходит (тест 26.10). Why: единственный способ частичной выплаты по спору. -> stays here
- Доля исполнителя в рахунку = цена + комиссия банка, доля платформы = 5 % от цены. Why: банк удерживает эквайринг из доли исполнителя (пример менеджера), исполнитель получает цену полностью. Проверить: комиссия на тестовых цифрах недостоверна. -> stays here
- При частичной выплате комиссия платформы финализируется пропорционально числу выплаченных частей исполнителя. Why: простое правило, не наказывает исполнителя за спор целиком. Меняется в одной функции `planPayout`. -> stays here
- Один этап = один счёт Monobank с `paymentType: hold`, `X-Cms: findlyfy`. Получатели сплита фиксируются в счёте (в тесте идентификаторы в списке меняются при каждом запросе). -> stays here
- Токен приложения читаем из `MONOBANK_TOKEN` (как в Укошике), для скриптов разведки `MONO_TEST_TOKEN`. -> stays here
- Второй провайдер для исполнителей без счёта ФОП в mono: UAPAY (решение владельца 27.10). Код не пишем, пока нет ключа магазина, ответов менеджера и мнения юриста/бухгалтера; платёжный слой делаем нейтральным к провайдеру. -> stays here
- Клиент и вебхук переносим из Укошика (свой проект), дописываем hold и finalize. -> stays here
- Частичная выплата по спору окончательная: после частичной финализации банк не даёт вернуть выплаченную часть того же получателя (`already been partially cancelled`, проверено на обоих получателях). Why: нефинализированные части банк считает частично отменёнными. Следствие: решение «выплатить 60 %» нельзя откатить, модератор подтверждает его явно. -> stays here

## Lessons (candidates)

- Тестовые идентификаторы получателей меняются при каждом запросе: хранить id из самого счёта.
- Банк принимает финализацию на произвольную сумму только с корзиной из точных исходных позиций.
- После частичной финализации возврат выплаченных позиций заблокирован: проверять правила банка на всех шагах цепочки, а не только на первом.
