## Decisions

- Профиль: прямой заход идёт на `app/(site)/p/[id]` (без карты), открытие с карты перехватывает `app/(map)/@modal/(.)p/[id]` (параллельный слот `modal` в layout карты). Не стал оставлять страницу в `(map)` с серверным блоком под диалогом: тогда прямой заход грузил бы карту (1,6 МБ), а S-6 требует группу без неё. Файл `lib/profile/navigation.ts` и диалог не менялись. (why: наименьшее вмешательство в поведение внутри приложения при цене S-6) -> stays here
- Видимые на карте для каталога: опубликованный профиль и уровень размещения от 2, как в `/api/map/performers`. Сами профили (`/p/<id>`) доступны при любом уровне, как раньше.
- Слаги тегов по умолчанию равны id (уже латиница и дефисы); 12 слагов с «человеческим» видом (`lendynhy`, `telegram-boty`...). Заголовки написаны для 70 тегов, у остальных заголовок равен названию тега. Id тега, чей слаг другой, адресом не считается (404).
- Тонкая страница каталога при закрытом сайте оставляет общий `noindex, nofollow` (`siteRobots()`), `noindex, follow` ставится, только когда индекс открыт.
- Демо-исполнители (`demo-…`) показываются в списке (на dev иначе каталог пуст), но в порог индексации не входят.
- Ссылка работы профиля выводится только при `http(s)://` (в D1 лежит свободный текст пользователя).
- В карточке нет отдельного OG-изображения: S-2 упоминает «свою OG-картинку», в объём этой задачи она не входила.
- Видимых изменений главной нет; серверный блок под картой (`h1`, категории, города, свежие запросы ссылками) не строил.

## Not verified

- Не открывал страницы ни в браузере, ни на dev (запрещено поручением): не видел ни рендера `/p/<id>` и `/poslugy/...` на 375 px и десктопе, ни клавиатуры с фокусом (DONE-2).

Это главный риск пакета; если слот не сработает, прямой путь `/p/<id>` всё равно рабочий, но открытие с карты перезагрузит карту.
- Не проверено, что `curl` отдаёт `h1` и JSON-LD (в тестах рендер страниц не гоняется, проверены данные и сборка). Ответ 404 для неизвестных слагов проверен только по коду `notFound()`.
- Выбор «чанки без MapLibre» сделан по подстроке `maplibre` в чанках; на главной та же проверка тоже даёт 0 (карта грузится лениво), поэтому это подтверждает малый размер (496 КБ против 1,6 МБ), но не доказывает отсутствие карты строго.
- Нагрузка: страница каталога читает все опубликованные профили и уровни (до 500), как `/api/map/performers`, но без кеша края. Замеров нет.
- Заголовки тегов написаны мной по смыслу, не сверены с частотностью запросов (S-7 не делался).
