## Goal

Запрос больше не висит вечно: через 14 дней автору приходит вопрос «Ще актуально?», без ответа запрос закрывается сам и его можно открыть снова. Заказчик выбирает исполнителя: у отклика есть серверный статус, а «Обрати» ведёт в чат и оформление сделки. Список «Мої запити» перестаёт делать по запросу на каждый запрос ради счётчика. Пакет F из `2026-11-15-project-review.md` (R-3, R-5, R-8, решение 4).

## Decisions

- Срок жизни считается от `renewed_at` (публикация или последнее «Так, ще актуально»); пустое значение читается как `created_at`. Правка текста срок не продлевает (why: автор может править запрос, который давно не нужен). -> `docs/features/requests.md`
- Вопрос ставится один раз на срок: `renewal_asked_at` занимается условным UPDATE, поэтому повторный или параллельный tick ничего не дублирует. Ключ уведомления содержит получателя и начало срока (why: урок из ревью про ключ без получателя). -> `docs/features/requests.md`
- Вид уведомления `offers`: отдельного переключателя в настройках нет, он только усложнил бы настройки (why: вне области пакета). Если человек отключил «пропозиції» или сидит на сайте, сообщения не будет, вопрос при этом виден в «Мої запити», а автозакрытие идёт по таймеру. -> `docs/features/requests.md`
- Окно восстановления для `expired` 7 дней, для закрытия самим автором по-прежнему 24 часа; любое восстановление начинает срок жизни заново (why: иначе запрос закрылся бы при ближайшем tick). -> `docs/features/requests.md`
- `chosen` не уникален: автор может выбрать нескольких. Сервер не снимает `chosen` с других (why: сделок по одному запросу может быть несколько, правила выбора владелец не задавал).
- Исполнитель статус не видит: `myResponses` и экран отклика не получают поля. Отклонённый отклик для него выглядит как обычный.
- Рейт-лимит `responseStatus` 120 в час (why: `requestEdit` на 20 в час слишком мал для разбора списка).
- Статусы закрытого запроса не меняются (409). Опрос 4 с подтягивает статусы с другого устройства в уже показанные карточки.
