# i18n

- COMP-8. No hardcoded user-visible text in code, including `aria-label`, `alt`, `title`, placeholders and error messages; everything goes through the i18n layer. Why: strings hidden in JSX never reach translation; ukoshiku still has such gaps in its assistant. Check: review.
- LANG-1. The project's `AGENTS.md` names the default locale, the supported locales and any language that must stay out of the product. Why: agents otherwise translate or add locales on their own. Check: review.
- LANG-2. Keys are stable, readable and namespaced by feature; a new key is added to every supported locale in the same PR, or the missing-locale fallback is stated in the PR. Why: a key in one locale shows raw keys in the others. Check: review (a key-parity unit test is recommended). Example: ukoshiku/messages
- LANG-3. Numbers, dates and money are formatted through locale-aware helpers (`Intl`), never by string concatenation. Why: separators and currency position differ per locale. Check: review.
- LANG-4. Copy the owner has approved is source content: do not rewrite, shorten or "fix" it without an explicit request, and protect it with a fingerprint test where it matters. Why: Demo locked its approved role-report copy this way. Check: unit test.
