# Styles and tokens

- CSS-1. Default: Tailwind utilities in JSX, and a stylesheet only for what utilities cannot express (complex states, keyframes). Where a project keeps feature CSS, one block (class prefix) is one stylesheet in its component folder, imported by that component; a route loads only its own files; global CSS holds only reset, token bridge, base typography, focus fallback and print. Move blocks without renaming classes, delete dead rules and merge duplicate selectors during the move; a deferred-loading entry file may only `@import` section files. Why: Demo's paywall lived inside 18,000 lines of landing CSS and every page loaded one feature's preview styles. Check: review, Stylelint `no-duplicate-selectors`.
- CSS-2. Raw colour literals (`#hex`, `rgb()`, `hsl()`, `oklch()`) appear only in the token file; feature CSS uses `var(--token)`, local variables point at tokens not hex, and JSX uses semantic utilities (`text-muted-foreground`), never the Tailwind palette (`text-slate-500`, `text-red-600`). Why: Demo had about 1,400 colours outside tokens and 115 palette classes. Check: Stylelint `color-no-hex` and `function-disallowed-list`, ESLint `no-restricted-syntax` (palette regex). Example: ukoshiku/stylelint.config.mjs
- CSS-3. Spacing, radius, shadow, type size and z-index come from the token or Tailwind scale; raw px for these stays inside primitives, and z-index uses named layers (`z-modal`), not numbers or inline `zIndex`. Why: Demo set 407 radii and 292 shadows as raw values. Check: review.
- CSS-4. No `!important` except to beat third-party CSS, with a comment; `style={{}}` only for runtime values (animation delay, measured size, CSS variables); static values become utilities (`@utility z-modal`). A justified exception gets a file-level `eslint-disable <rule> -- reason`. Why: Demo carried 83 `!important` in one file because specificity was beaten, not fixed. Check: Stylelint `declaration-no-important`, ESLint `no-restricted-syntax` (static inline style).
- CSS-5. A selector is declared once per file: change the existing rule instead of appending an override at the end. Why: one Demo selector was declared 8 times. Check: Stylelint `no-duplicate-selectors`, `declaration-block-no-duplicate-properties`.
- CSS-6. Removing or replacing markup removes its CSS in the same PR, and no `-v2` lives beside `-v1`. Why: at least 240 of 1,970 Demo classes were unused. Check: review (class-usage audit).
- CSS-7. CSS media queries and Tailwind screens use one breakpoint set, named in DESIGN.md. Why: Demo's CSS used 520, 540, 1180, 1200 and 1320 px that Tailwind did not have, so a page reflowed at different widths per block. Check: review.
- CSS-8. Content hidden until deferred CSS loads (`visibility: hidden`) must become visible without JS and must not stay hidden if loading fails. Why: on slow JS the lower landing stayed invisible. Check: review.
- CSS-9. One token per meaning: no second name for the same value (`--bg`, `--preview-bg`, `--profile-bg`); during a migration the old names stay as aliases of the new one. Why: Demo had three names for one background and two near-identical oranges. Check: review.
- CSS-10. Type sizes, including the smallest, are tokens named in DESIGN.md; a fluid size (`clamp`) is defined once as a token, never inline, and text is not scaled with `vw`. Why: Demo counted 91 `clamp`/`vw` font sizes against its own rule. Check: review, ESLint `no-restricted-syntax` on `text-[`.
