# Components and design system

- DS-2. `<button>`, `<input>`, `<select>`, `<textarea>` appear only inside `components/ui/*`; feature code uses `Button` (`size="icon"` plus `aria-label` for icon actions), `Input`, `Select`, `Textarea`, `DropdownMenu` for menu items, or a shared choice primitive for selectable cards. Allowed: a hidden `type="file"` input behind a `Button`, third-party widgets that need their own element. Why: Demo had 60 native buttons beside 74 `Button`s. Check: ESLint `no-restricted-syntax` on JSXOpeningElement button/input/select/textarea, off in `components/ui`. Example: ukoshiku/components/ui/button.tsx
- DS-4. `className` on a primitive sets layout only (margin, width, grid or flex placement); colour, border, radius, shadow, font, size and interaction states come from variants. A different look is a new variant. Why: overrides fork the primitive and break when it changes. Check: review.
- DS-5. Dialogs, drawers, sheets, popovers and menus use the shared primitive, which owns focus trap, focus return, Escape, scroll lock and portal; on mobile use the drawer. Before replacing a hand-made overlay, check those four behaviours on the new one. Why: Demo's checkout modals were `role="dialog"` on a plain div with none of them. Check: ESLint `no-restricted-syntax` on JSXAttribute `role="dialog"` outside `components/ui`. Example: ukoshiku/components/ui/drawer.tsx
- DS-6. No proxy hacks: no classes that copy a primitive's hover or focus onto another element (`*-hover-proxy`); make the element a real primitive (`Button asChild`). Why: Demo copied a button's hover onto a div. Check: review.
- DS-7. Every control has an accessible name (icon-only: `aria-label`), a visible focus ring and a target size from DESIGN.md tokens; labels are visible, a placeholder is an example, not a label. Why: icon buttons without names and thin targets are the usual audit findings. Check: ESLint `jsx-a11y` rules (eslint-plugin-jsx-a11y through the shared config), review. Example: Demo/DemoWorkSpace/components/ui/close-button.tsx
- DS-8. Status, errors and validity are never shown by colour alone (add icon or word), and text meets WCAG AA contrast. Why: colour-only state fails colour-blind users and bright screens. Check: review, axe or Lighthouse.
- COMP-3. A file or component that does more than one thing is split by responsibility (ARCH-1), whatever its length; a long one that does one thing stays whole. Split a component by zone (header, list, form, empty state) into `parts/` in the same folder, with its CSS; split a hook that grew by concern. Why: `ProfileCatalog.tsx` rendered, fetched and held state for a whole page. Check: review; ESLint `max-lines` as a warning at 400 per file (skip blank lines and comments) is a smoke detector that prompts a responsibility check, not a target.
- COMP-5. One implementation per helper (`cn`, formatters, fetch wrappers); unused components, hooks, exports and dependencies are deleted, and no `-v2` copy lives next to the old one. Why: Demo had two `cn` files and four unused hooks. Check: `knip`. Example: ukoshiku/knip.json
- COMP-9. Every async view has loading (skeleton), empty and error (with retry) states. Why: a view without them shows a blank screen on slow or failed requests. Check: review.
